# 18. The v0.6.0 plan

> Part of the [design index](../../DESIGN.md).

Status: **delivered** — phases 0–9 shipped as PRs into `v0.6.0` on 2026-11-14;
the evidence per phase and what is operational are in
[`docs/features/v0.6-close/report.md`](../features/v0.6-close/report.md). Base
branch `v0.6.0`, cut from the `v0.5.0` tag at `ea3b86d`. This document turns
M4–M5 ([§11](11-roadmap.md)) into PR-sized phases; the milestones remain those of
the roadmap.

## Entry conditions

- `v0.5.0` is the code and contract baseline (M0–M3, auth boundary, quality pass).
- The v0.4 feature inventory is a **scope reference**, not the gate: v0.6.0 builds
  on the v0.5.0 contract.
- The release follow-ups in [§17 §0](17-deferred.md#0-v050-release-follow-ups) are
  operational: green CI once billing is restored, a GitHub Release, and an
  artifact workflow decision.

## Strategy

1. **Service apps first.** Terminal, fs, proc, net, storage and accounts need
   kernel-facing work; without the service contract they would leak ambient
   authority or force engine edits.
2. **Host emulator second.** A removable mock service implements the same
   protocol with deterministic fixtures, so the apps and panels can be built
   before the real services exist.
3. **Then one real service at a time**, tested on a real machine before the next.
4. **M4 first, M5 second.** The terminal is the real consumer that streams will be
   designed against.
5. **One phase per PR against `v0.6.0`.** Each phase is demoable and reversible.
6. **No feature logic in the engine.** A phase that cannot be expressed as a
   bundle, a service or an SDK addition is a design problem, not an engine patch.
7. **The panel stays a client.** New UI arrives as `panel.view`/`panel.settings`
   contributions.

## Service manifest (decision)

Service bundles use **`manifest_version = 3`**. Existing v2 apps keep working
unchanged. A v3 app may be service-only, wasm-only or **hybrid**:

- service-only: `[service]` with binary path, sha256, class, argv and socket;
  WIT exports; no `[wasm]`;
- wasm-only: the v2 feature set under v3;
- hybrid: both halves in one bundle, with disjoint exports and the grant risk as
  the maximum of the import risk and the class risk.

The public API is always WIT. A service answers `interface#function` over the
private `/__anth/call` RPC; there are no raw `/service/*` routes. The binary hash
lives in the signed manifest and is verified like the wasm hash. The bundle layout
gains `bin/`.

Third-party service bundles are refused unless the daemon starts with
`[services] allow-third-party = true`.

## Phases

### Phase 0 — Baseline inventory and ADRs

**PR:** `docs: v0.6.0 baseline inventory and service ADRs`

- Fix the v0.5.0 baseline and the v0.4 checklist as reference.
- Record the v3 service schema (service-only, wasm-only and hybrid), classes
  (`exec`, `socket`, `device`, `admin`, `host`), argv allowlisting, WIT-RPC and
  the third-party switch.
- Record the `fs` host-root model and the terminal WIT interface.
- Record that streams, events and quotas stay in M5.

**Done when:** decisions are in the decision log and the baseline checklist is
linked from [§13](13-migration.md). No engine code. The detailed contract is
[§19](19-v0.6-baseline.md).

### Phase 1 — Service app contract

**PR:** `feat: service apps and the supervisor socket`

- Contract v3, registry/bundle support, grant/risk for service classes, and the
  hybrid `[service]` + `[wasm]` shape.
- `[services] allow-third-party` read at boot; false refuses a third-party
  service at install, true allows it through approval.
- Supervisor: launch, readiness, stop, crash isolation and audit.
- WIT-RPC: `/__anth/call` over the service socket, shared value codec,
  `ServiceCaller` behind `AppCaller`, and route/CLI dispatch to service providers.
- Fixture `echo-service` and a hybrid fixture for the e2e.

**Done when:** the fixture installs, composes, answers through a WIT route and
CLI, is removed, and its socket disappears.

### Phase 2 — Host emulator and demo composition

**PRs:** `feat: service SDK and fs emulator`, then one bundle per app.

- A native emulator under `demo/emulator` (the plan's `apps/host-emulator`;
  outside the wasm workspace) implementing the real service protocol with
  deterministic fixtures.
- **One bundle per app**, because a bundle carries one WIT package and one world:
  `fs`, `terminal`, `proc`, `net`, `storage` and `accounts`, all six present.
  Each bundle keeps the future real app's package and id, so replacing the
  provider does not touch the UI.
- Unprivileged (`socket`), no host root, no engine knowledge.
- The demo composition also installs `org.anthracite.home` (answered by the same
  emulator with a host fixture) in place of Hello; `apps/hello` remains as the
  minimal example.
- `demo/config.toml` + `demo/composition.toml` compose the emulator. A developer
  build turns the third-party service switch on by default; release stays closed.

**Done when:** the same panel views render deterministic data from the emulator;
stopping it degrades the demo only.

### Phase 3 — System app UIs against the emulator

**PRs:** one per app, or paired only when they share no service code.

- `fs` explorer, terminal view, process list, network status, storage and
  accounts screens.
- All UI is a `panel.view` contribution; no engine feature names.

### Phase 4 — Real `fs`

**PR:** `feat: filesystem service`

- `host` class, operator-approved root (default `/`), explicit audit.
- The wasm UI never receives a path; it calls the service socket.
- Traversal, symlink escape and non-UTF-8 names are typed refusals.

**Done when:** the user tests it on a real machine and the emulator can be
removed from that composition.

### Phase 5 — Real terminal

**PR:** `feat: terminal service`

- PTY open/write/resize/signals/close/half-close over the versioned HTTP service
  protocol.
- Budgets for bytes and lifetime; a crash degrades only the terminal.

**Done when:** the user tests it on a real machine; no path or capability leaks
into the wasm UI.

### Phase 6 — Real proc, net, storage, accounts and firewall

**PRs:** one per app; `net` may split into read-only and interface apply.

- `proc`: list and signal with allowlist and `admin`.
- `net`: status/read first; interface apply is a separate approved flow.
- `firewall`: its own app and bundle, grouped under Network as a sub-tab. One
  managed `inet anthracite` nftables table with input/output chains, rule CRUD,
  flush and default policy, always through `nft` argv and never a shell. Network
  only groups it visually; it cannot call the firewall app.
- `storage`: disks, mounts and usage; read-only first.
- `accounts`: local users/groups, create/delete, lock, password, group CRUD,
  `getent`/`source`, GECOS and home removal across `accounts@1.1.0` then
  `accounts@1.2.0`. Mutations run only with the approved argv policy.

**Done when:** each is removable, removing `net` leaves a working system with
Firewall as a top-level tab, not a broken panel, and the firewall sub-tab can
list, add, flush and reset the managed table's rules under its own approval and
`host` class.

### Phase 7 — Manager and M4 close

**PRs:** `feat: panel manager`, `test: v0.6.0 system composition`

- Manager: panel chrome (topbar → Manager) over the existing `/api/engine/*`:
  installed apps, enable/disable/remove, approval with the risk flags, revoke,
  install/upgrade from a file, and the composition document.
- It is **not an app bundle**: an app module runs in the sandboxed frame and may
  only call its own `/api/apps/{id}/` prefix. A bundle-based manager waits for
  the system tier and its signed distribution key; granting engine management to
  a third-party bundle now would be a privilege bypass (`D-Manager-Panel`).
- Golden composition of the system apps on the v0.5.0 contract.
- Remove `net` and assert the rest still boots and renders.

### Phase 8 — Streams, typed events and quotas (M5)

**PRs:** `feat: streams`, `feat: typed events`, `feat: stream quotas`

- `stream<T>`/`future<T>` and HTTP chunked/SSE mapping.
- Backpressure, cancellation, half-close and error-after-partial-data each with a
  conformance test.
- Events as `subscribe() -> stream<event>`; per-stream bytes/s and total quotas.
- Retrofit the terminal to WIT streams; the service HTTP protocol stays as the
  service boundary.

### Phase 9 — Conformance, third party and hardening (M5)

**PRs:** `feat: publish anth-conformance`, `feat: provider WIT fetch`,
`feat: audit and approval UI`, `feat: service sandbox`

- The kit runs offline against a bundle; `anth app fetch-wit` resolves provider
  packages.
- Panel settings: audit, risk and authority diff.
- Service sandbox hardening; Pulley decision after the sandbox.
- External bundle acid test: installs, composes, renders and answers.

## Cross-cutting rules

- **Manifest changes are contract changes.** v2 stays frozen; v3 is the service
  contract.
- **Service authority is narrower than the grant.** The grant lists interfaces and
  classes; the supervisor checks binary, argv and class.
- **No paths to wasm apps.** The `fs` service gets the host root; the UI gets only
  the service socket.
- **Audit every service lifecycle.** Launch, refusal, crash, stop and proxy denial.
- **CI:** every phase adds unit/e2e coverage; the v0.5.0 remote-client and edge
  checks stay.

## Open decisions

All Phase 0 decisions were agreed before engine work:

| # | Decision |
| --- | --- |
| P1 | v3 supports service-only, wasm-only and hybrid apps; services export WIT, not raw routes; v2 is unchanged. |
| P2 | Streams/events/quotas wait for M5; the terminal exports WIT functions with bounded reads. |
| P3 | The real `fs` service gets an operator-approved host root; the wasm UI never receives paths. |
| P4 | `net` is read-only first; apply is a separate approval flow. |
| P5 | The v0.5.0 tag is the baseline; the v0.4 inventory is a scope checklist, not the gate. |
| P6 | Pulley waits until after the service sandbox. |
| P7 | The host emulator is a removable service bundle, not engine code. |
| P8 | Third-party service bundles are allowed only with `[services] allow-third-party = true` at daemon start; default false. |

## Definition of done

- The system apps work on the v0.5.0 contract, and removing `net` leaves a
  working system.
- An app outside this repository installs, composes, renders and answers.
- The conformance kit fails loudly on a bundle that lies.
