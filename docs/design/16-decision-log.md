# 16. Decision log

> Part of the [design index](../../DESIGN.md).

Decisions taken during the v0.5.0 review. Binding until superseded.

| ID | Decision | Why |
| --- | --- | --- |
| R1.1 | v0.5.0 ends at M3; features return in v0.6.0 | The platform is judged by its contract, not its catalogue |
| R1.2 | WebAssembly Component Model + WIT from day one | One type system, real tooling, multi-language apps |
| R1.3 | *Superseded by R1.3-rev.* Shell as an app, with a bootstrap document served by the engine | First pass; replaced once the panel became an application |
| R1.4 | Iframe sandbox per app | The authority model matters more than theming convenience |
| R1.5 | Install, approve and compose are separate acts | Three different questions, three auditable states |
| D-Runtime | wasmtime + Cranelift, single backend | Reference implementation; lets wasm do heavy work |
| D-Pulley | Pulley documented, not shipped | W^X hosts are a deployment profile, not the default |
| D-Linking | Direct typed links app→app; broker only for host interfaces | Fighting the linker costs weeks and buys little |
| R2.1 | WIT ids for interfaces; reverse-DNS for apps; app WIT namespace declared | WIT cannot express DNS-shaped names |
| R2.2 | Exact interface versions | What the linker requires; evolve by exporting two versions |
| R2.3 | Manifest is an index; the WIT package lives under `wit/` and is signed (refined by D-Wit-Package) | WIT is a language, not a config string |
| R2.4 | Events are typed notifications, not a topic bus | Confirmed; deferred to v0.6.0 because the mechanism needs streams |
| R2.5 | CLI and clients generated from WIT | Hand-written surfaces drift; v0.4.0 proved it |
| R2.6 | State is interfaces only; never paths | A path is ambient authority |
| R2.7 | `anth:error@1` with a fixed HTTP mapping | One error model for HTTP, CLI and clients |
| R2.8 | The component world is validated against the grant before linking | A link is authority; a lying manifest must not run |
| D-Streams | Streams and typed events land in v0.6.0/M5, designed against the terminal; the runtime is pre-shaped now | A stream designed without a real consumer gets redesigned at the PTY anyway |
| R3.1 | Risk is computed over the resolved import graph, never declared by the manifest | A manifest that declares its own risk can lie about it |
| R3.2 | One interface, one risk level; split mixed interfaces | Grants are per interface, so a mixed interface forces the highest level |
| R3.3 | Distribution key compiled in; the operator keyring only extends `third-party` trust | A config file must never be able to mint privilege |
| R3.4 | An upgrade auto-applies only on an empty authority delta | Re-approving every patch trains operators to click through approvals |
| R3.5 | Static misses fail the composition; runtime failures degrade (refined by D-Fatal-Rule) | A silent degraded boot hides operator mistakes; a crash must not take the engine down |
| R3.6 | No revocation in v0.5.0: uninstall or rotate the distribution key | Honest limitation; a CRL only when a fleet needs it |
| R1.3-rev | The engine serves no UI. The panel is an application that hosts apps | A shell bundled as an app still put UI concerns in the platform; a headless engine keeps the thesis literal |
| D-Workspace | Four Rust workspaces and three Bun ones, with a shared target dir and CI-checked forbidden edges | The isolation must be unrepresentable, not merely documented |
| D-CLI | The CLI lives in `sdk/rust/cli` and builds the `anth` binary; the distribution ships it beside the panel (refined by D-Cli-Surface) | The engine's commands are not a panel's private feature |
| D-Remote | The engine must stay usable by a panel in another process; v0.5.0 ships only the linked mode | The API is the product boundary; an in-process shortcut would quietly close that door |
| D-Target | One shared `build.target-dir` for the Rust workspaces | Separate workspaces buy isolation, not a second compiler |
| D-HTTP | The API is resources, not commands: `POST` installs, `PUT` replaces and approves, `PATCH` toggles state, `DELETE` removes and revokes | Actions exposed as invented verbs drift from the resources they mutate, and cannot be retried safely |
| D-Compose-PUT | The composition is replaced as a whole document with `If-Match` | A read-modify-write of a document needs a precondition, not an `add` endpoint |
| D-Install | `POST /api/engine/apps` creates and derives the id; `PUT /apps/{id}` only replaces | The id lives inside the bundle, so a client cannot name it before uploading |
| D-Services | `service` apps arrive in v0.6.0 with the terminal; v0.5.0 ships wasm and ui | A binary that cannot speak WIT is an exception to the type system, and it needs its first real consumer to be designed |
| D-Slots | The SDK owns the slot vocabulary (`panel.view`, `panel.action`, `panel.settings`); a panel declares which it implements; the engine validates only the format | Portable apps need a contract-owned vocabulary, and the engine must not learn UI |
| D-Blobs | Blobs are not in the v0.5.0 native set; they arrive with transfers in v0.6.0 as `stream<u8>` | The resolver treats the native set as always available, and `bytes` would have to change contract when streams land |
| D-Wit-Package | The WIT package lives implicitly under `wit/`; its name and version come from `[app] namespace` and `version`; exactly one world | One package name written once, and a world that has a home |
| D-Cli | `anth app <alias> <verb>`; the CLI surface comes from the composition; three output views with `--table` by default; exit codes follow `ErrorKind` | Only composed apps can be invoked, and the CLI must not become a generic HTTP client |
| D-Format | TOML for manifest, composition, config and grants; JSON for the API; YAML only as a CLI output view | Implicit typing in a signed artifact is a silent change, and YAML editing drops the comments an operator needs |
| D-Credentials | First boot generates operator name and password into `state/credentials.txt` (`0600`) and forces a change on first login | A default account is a hole, and a secret in the log is a leak |
| D-Health | `/health` is unauthenticated liveness; `/api/health` is authenticated readiness and answers `503` until ready | Liveness and readiness answer different questions; one endpoint cannot be both |
| D-Remote-Impl | Only the linked panel is implemented in v0.5.0; HTTP stays as a designed transport | The SDK keeps the door open without paying for it |
| D-Namespace | `anth` for the engine, `anthracite` for first-party apps, everything else for third parties | A reserved namespace only the engine can use prevents an app from impersonating the host |
| D-Host-Wit | `engine/wit/` is the host catalog: `anth:error/kinds`, `anth:env/{info,time,log,random}` and `anth:store/kv` as WIT packages under `deps/`; the ids match `catalog::NATIVE` plus the injected `anth:error/kinds`, and `host.wit` imports the five native interfaces | The SDK and the resolver both need one parseable source; a CI test compares the packages with the closed native set so neither drifts |
| D-Host-Env | The wasmtime backend implements `anth:env`: hostname/os/arch/uptime/cpu/memory cached once per process, wall and process-wide monotonic time, stderr logging filtered by `LogSettings` (text or JSON), and `/dev/urandom` capped at 4 KiB per call (`too-large` beyond it). Only interfaces the grant lists are linked, after the world check | The environment interfaces are what every app needs before routes; the store has its own decision |
| D-Host-Store | `anth:store/kv` is one JSON map per app at `state/data/<app-id>/kv.json`, written atomically at `0600`, keys ≤ 1 KiB, values ≤ 1 MiB and total ≤ 4 MiB; it is linked only when the grant lists it and the app has a data directory | A flat namespaced map needs no path handling in the app, and the format is small enough to rewrite atomically; the total cap keeps every write readable by the loader. Broker auditing and per-app quotas land with the broker |
| D-Boot | The daemon resolves the composition, then starts each running app through the supervisor with its grant, wasm hash check, budget and `data` directory; a failed instantiation degrades that app and its dependents, and a fatal resolution is reported while the API keeps serving so the document can be repaired | Boot must not lock the operator out of the tool that fixes a broken composition, and one broken app must not stop the others |
| D-Routes | `/api/apps/{id}/{path}` dispatches only for an app that resolves as running, only to a `[[route]]` whose method and path match, and only through the `AppCaller`; `GET`/`HEAD`/`DELETE` take query parameters, other methods a JSON object body, a body on a no-body method is `400`, `OPTIONS` is answered by the engine with `Allow`, and an undeclared method is `405` with that list | The manifest is the index and the resolver decides what runs; keeping dispatch behind a trait lets the daemon run apps while a host that only mounts the router still refuses with `unavailable` |
| D-Cli-Invocation | `anth app <alias> <verb>` resolves the alias in `/api/engine/apps` and the verb in the composition surface, then calls the `[[route]]` bound to the same `interface#function`; a verb with no route is `unavailable` | v0.5.0 has no generic call endpoint, and adding one would create a second path into an app; the route is the one audited door |
| D-Assets | `/api/apps/{id}/assets/{module}` serves only a `slot.module` declared by a running app's manifest, re-hashes the bytes against `slot.sha256`, answers `ETag: "<sha256>"` and `Cache-Control: immutable`, `304` on `If-None-Match`, and an empty `HEAD` | The panel needs hash-pinned modules, and restricting the path to the manifest's own list keeps asset serving from becoming a general file read |
| D-Mapping | One HTTP ↔ WIT mapping, implemented once in the router and reused by codegen | Three implementations of the same rule is three chances to disagree |
| D-Slot-Contract | A slot contribution is an ES module exporting `mount(root, ctx) -> cleanup` | Without a written contract, every panel invites a different module shape |
| D-Signature-Message | Signature covers a canonical, sorted, length-prefixed manifest set (`manifest.toml` + every file under `wit/`), with plain names over `[A-Za-z0-9._/-]` | The format must be written once and pinned by a test vector, not inferred from code; NUL is the separator, so control bytes in a name would make the encoding ambiguous |
| D-Signature-Algorithm | `manifest.sig` is the 64-byte **Ed25519** signature over that canonical message, in standard base64; a key's fingerprint is the lowercase hex SHA-256 of its 32-byte public key | Ed25519 is deterministic and has a mature Rust implementation; base64 keeps the artifact one line and the fingerprint fits a filename |
| D-Wit-Hash | `wit_sha256` is the SHA-256 of `"anth-wit-set-v1\0"` followed by the sorted `wit/*.wit` files framed as `name \0 u64le(length) bytes` | The grant freezes the WIT set; reusing the signed-message framing under its own prefix keeps one rule and one parser |
| D-Distribution-Key | v0.5.0 compiles **no** distribution key: every signed bundle is `third-party` through the keyring. The `system` tier lands with the release key in v0.6.0 ([§17](17-deferred.md#39-the-distribution-key-and-the-system-tier)) | With no release process yet, a compiled key would be a key nobody can rotate and nobody can use; the keyring is the honest v0.5.0 trust model |
| D-Interface-Versioning | The WIT package version versions the interface set; `[app] version` is the app's own version and need not match it. Every exported interface id carries the package version | WIT has no per-interface version, and tying ids to every app release would force consumers to relink for changes that touched no type |
| D-World-Signature | A world signature is lowercase hex SHA-256 of the interface's canonical WIT text (`interface <name> { … }`, declarations sorted, no whitespace); if the expected world has one, the component must match it and a missing actual signature is drift | Name and version do not catch a type change that kept the interface id; the runtime compares canonical text, and the contract owns the one form both sides use |
| D-Descriptor | `apps/<id>/descriptor.toml` holds the operator's mutable facts (`enabled`, `alias`) and the install facts (`signer`, `tier`, `installed_at`) | The manifest is signed by the author and the grant freezes authority; toggling or renaming an app must rewrite neither |
| D-Alias | The descriptor's alias overrides the manifest's; an operator alias may not collide with another installed app's effective alias, while two fallbacks may collide and the CLI uses the full id | Two apps answering one CLI verb is ambiguous, and the operator must be able to rename without a new signed manifest |
| D-Binding | No provider map: the interface id is the binding, and a second implementation is a different interface | A configuration table with nothing to decide is a source of contradictions |
| D-Failure-Phases | Failures are classified by phase: resolve failures are fatal, instantiation and runtime failures degrade | A graph error and a broken app deserve different severity |
| D-Fatal-Rule | A composition error is fatal only when it can be fixed without the engine running | Otherwise the engine locks the operator out of the tool that repairs it |
| D-Error-Envelope | `{"error":{"code","message","app?","detail?"}}`; the app's six codes plus four engine codes; unknown codes read as `internal` | One contract shared by HTTP, CLI and clients, extensible without breaking readers |
| D-Cli-Surface | The CLI has generated app verbs and a fixed engine command set; `anth status` reads health plus composition | The management half was never specified, which is how a command that does not exist gets cited |
| D-Surface | `GET /api/engine/composition` returns `composition` plus a `surface` with `apps` in boot order (each with its manifest `routes`, `slots` and `cli`), `degraded` (kebab-case reason and optional detail), `links` whose provider is `engine` or an app id, and `fatal` when the document would refuse a boot | The panel and `anth status` need the same answer to "what runs and why not" without parsing manifests, and a fatal document must stay readable so it can be repaired |
| D-Composition-ETag | The composition `ETag` is the quoted SHA-256 of its canonical TOML; `PUT` requires `If-Match` (or `*`) and answers `412 precondition-failed` otherwise | The document is edited client-side, so a stale base must not overwrite a newer one; deriving the validator from the bytes avoids a separate version counter |
| D-Peer-Auth | The Unix socket authenticates by peer credentials; TCP authenticates by session | The kernel-issued identity needs no stored secret, and remote access keeps a real session |
| D-Syscalls | Syscalls go through the `nix` crate where it covers them; `libc` remains for what it does not (seccomp, landlock, new syscalls). Deferred to the service layer ([§17](17-deferred.md#38-nix-for-syscalls)) | Today's surface is four trivial `unsafe` lines; the service layer's `prctl`, `setsid` and signal work will justify it |
| D-Acknowledge | Breaking actions return `409` with `detail.acknowledge`; `--acknowledge <token>` proceeds and is audited | In a security contingency the operator must be able to act, and the record of acting knowingly is worth more than a prohibition |
| D-Grant-Scope | A grant freezes what an app imports, not who provides it | The provider changes with the composition, and a grant must not lie when it does |
| D-Risk-Recheck | Risk is computed at approval over installed apps and re-checked at compose; a growth blocks the app until re-approved | An app cannot gain authority because its provider was swapped |

| D-Build-Target | Apps build for `wasm32-unknown-unknown` and are wrapped with `wasm-tools component embed` + `component new`; `wasm32-wasip2` is not used | The wasip2 target links WASI interfaces nobody granted, and the world check would refuse every app built with it |
| D-Streams-Contract | Streams and futures are values returned by synchronous functions; `async func` is not used in WIT; concurrency lives inside the guest and in `anth-runtime` | An async export makes asynchrony contagious up to the router and gives HTTP two shapes |
| D-Exhausted | A budget trap maps to `exhausted` (503, exit 5) with `detail.budget`, not `internal` | Running out of granted fuel is a policy outcome, not a bug |
| D-Type-Introspection | The router reads parameter and result types from `component_type()` at runtime; unsupported types are refused at install | An installed app is an artifact, so its signature is read rather than assumed |
| D-Protocol | The API speaks protocol `1`; a client refuses an unknown protocol instead of guessing | v0.5.0 shares nothing with the v0.4.0 protocol `4`, and inheriting the number would imply compatibility that does not exist |
| D-State-Layout | `state/` has one fixed tree (apps, grants, composition, credentials, keys, data, audit) with `0700`/`0600` and no symlinks | A directory the engine creates on first boot cannot be left to interpretation |
| D-Audit | One JSON object per line, append-only, with `at`, `actor`, `action`, `app`, `result`, `detail`; denials are recorded even when nothing changed | The record of what an app tried is the point of having an audit |
| D-Audit-Actor | A socket request records the kernel uid (`uid:<n>`); a session request records the operator name | The kernel-issued identity is what the engine actually knows, and a session is an explicit claim it can verify |
| D-Upgrade-Approval | v0.5.0 revokes the grant on every `PUT /apps/{id}`: re-approval is always required. Authority-delta detection lands with upgrades in v0.6.0 | The engine cannot compare the delta yet, and a grant that survives an unseen bundle swap is exactly the authority growth D-Risk-Recheck exists to prevent |
| D-Demo | The demo is a composition profile in v0.6.0, not a build mode | Simulation is a different set of providers, not a different engine |
| D-Sessions | First boot writes `state/credentials.txt` (`0600`); TCP login mints an in-memory bearer session (12h by default) in an `HttpOnly; SameSite=Strict` cookie, and the first session is gated until the password changes. Five failures per source per minute block for 60s. `--reset-credentials` regenerates the file | The socket already has a kernel identity; TCP needs a revocable claim, and a password change revokes every token |
| D-Panel-Auth | The official panel has no shared Basic secret: it mounts the engine's session router, gates its shell on the same cookie, and exposes public `/login`, `/setup`, `/health` and the empty frame document | One authentication boundary instead of two secrets, and the shell cannot be read before the engine knows who is asking |
| D-Origin | Unsafe methods require `Origin` to match `Host` (or `X-Forwarded-Host` from a loopback peer); requests without `Origin` (CLI, curl) authenticate normally. Every API response carries CSP, `nosniff`, `no-referrer` and `X-Frame-Options: DENY` | `SameSite=Strict` is the first lock; the origin check is the second, and it must not trust a remote client's forwarded host |
| D-Service-Manifest | Service bundles use `manifest_version = 3` with `[service]` (binary hash, class, argv allowlist, socket) and no `[wasm]`/WIT exports; v2 apps stay unchanged | A new app kind and authority surface needs a new schema; reusing v2 would make one version mean two contracts |
| D-Host-Emulator | The demo host is a removable service bundle implementing the real service protocol with deterministic fixtures, not engine code | Iteration speed without contaminating the engine with feature logic |
| D-Fs-Root | The real `fs` service runs with class `host` and an operator-approved root (default `/`); the wasm UI never receives paths | The explorer needs host reach, but path authority stays in an auditable service |
| D-Streams-Order | The terminal ships over a versioned chunked HTTP service protocol; WIT streams, typed events and quotas land in M5 | Designing streams against a real terminal beats guessing; the retrofit stays bounded |
| D-V060-Baseline | v0.6.0 builds on the v0.5.0 contract; the v0.4 feature inventory is a scope checklist, not the gate | The contract is the baseline; v0.4 is a reference, not a reimplementation target |
