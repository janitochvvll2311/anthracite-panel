# v0.3.0 — architecture draft

Status: **draft**. This branch is a greenfield rewrite; the document is the plan
of record until a later revision replaces it. The former open questions are
resolved in §17. The decisions in §2 remain the working choices for the first
implementation; a later revision must change them explicitly, not by drift.

The v0.4.0 tree keeps this feature baseline and replaces the transport in §4:
HTTP is the only public dialect, served on TCP and on the Unix socket, and the
CLI is an HTTP client. See [phase-0-contracts.md](phase-0-contracts.md) §1.

Reference for the two previous trees: [reference-v0.1-v0.2.md](reference-v0.1-v0.2.md).
Phase 0 contracts under review: [phase-0-contracts.md](phase-0-contracts.md).

## 1. Position

v0.3.0 is not a port of v0.2.0 and not a cleanup of v0.1.0. It is the first tree
that has both:

- the **product scope** of v0.1.0: host inspection, processes, network,
  firewall, storage and partitions, accounts, files and archives, terminal,
  plugins, settings and lifecycle;
- the **structural guarantees** proven by v0.2.0: bounded framing, one error
  vocabulary, one dispatch site, real CI, authority owned by the daemon, and
  tests that can fail.

The rewrite should be finished enough to ship before any old tree is deleted.
The previous versions stay in git tags/branches; do not vendor `v1/` again.

### Non-goals for v0.3.0

- Multi-user roles or tenancy. One operator account is still the right shape
  until a second role has a consumer.
- A plugin marketplace, remote plugin registry or long-lived plugin process.
- Arbitrary scripting inside a plugin. A plugin supplies values and declares
  capabilities; the host owns execution.
- Live wire compatibility with v0.1.0 or v0.2.0. Migration is explicit.
- A generic operation framework before a second transport needs one.
- A windowing desktop, remote agents, clustering or a metrics backend.
- Streaming every read. Values stay values; only terminals and watches need
  different lifetimes.

## 3. Goals and quality attributes

### Security

- Every mutation is behind a policy switch that defaults to off in release.
- An empty allowlist denies everything.
- The daemon never builds a shell command. It runs an argv vector.
- A path is validated after resolution and again at the operation that writes.
- Secrets never appear in argv, logs, errors or API responses.
- A plugin cannot widen its own grant by rewriting its bundle or manifest.
- Authentication is on by default; the socket has its own peer check.

### Correctness

- One operation has one implementation, whichever transport reaches it.
- No silent truncation. A message that cannot be represented is an error; a
  list that can be long has a cursor.
- Guards read a fresh, unfitted snapshot.
- State has a named owner and a documented lifetime.

### Operability

- Static musl binary; no C dependency outside the pinned target's toolchain.
- Config that will not parse is refused, never replaced.
- `restart` applies a config change; `reboot` is opt-in and separate.
- Human and JSON logs; no global logger; no secrets.
- A health endpoint answers without a credential.

### Testability

- Every layer can be exercised without a real host where the host is not the
  subject: pure parsers, fake runners, injected clients, a real router.
- A fixture that is missing is a failure, never a silent skip.
- CI runs the shipped profile, not only the debug profile.
- The frontend can mount every panel with fake clients and no daemon.

### Footprint and performance

- Keep the static binary dependency-light: standard library for `/proc`,
  in-tree crypto or pure-Rust crates, no JIT.
- Bound memory, frames, waits, fuel and subprocess output.
- A slow disk, a quiet PTY or a spinning guest must not stall `/healthz`.

### Why these boundaries

- `anth-wire` is the contract an alternative client can implement. It must not
  depend on panel code.
- `anth-host` is pure parsing. It takes a filesystem root so tests can use
  fixtures; it never spawns or mutates.
- `anth-plugin` is the contract a guest links. It is `no_std`, has no panel
  dependency and no authority of its own.
- `anth-panel` owns every policy, guard and side effect.
- `frontend/anth-wire` mirrors the browser boundary; `anth-webui` owns the
  shell; `anth-plugin` stays independent of the panel's framework.
- Each plugin is a peer project with its own lockfile. `backend/` does not build
  plugin crates and `frontend/` does not install plugin dependencies.

## 5. Wire protocol

### Framing

- 4-byte big-endian payload length, then that many bytes of JSON.
- `MAX_FRAME_LEN = 64 MiB`. Exceeding it is `ErrorKind::TooLarge`; the daemon
  never shortens a message to fit.
- A frame contains exactly one message. JSON may contain newlines.
- `PROTOCOL_VERSION = 3` for the v0.3 line. v0.2 is 1; a mixed pair fails at
  the first message instead of misparsing later.
- Before `1.0.0`, breaking changes are allowed: bump `PROTOCOL_VERSION`, update
  the CLI and UI in the same change, and record the break in
  `docs/design/protocol-changelog.md`. There is no compatibility guarantee yet.
  The scaffold that makes the later policy possible is present now: the version
  constant, the mandatory handshake and a single place that rejects a mismatch.

### Handshake

- The first frame on a Unix-socket connection **must** be
  `Hello { protocol_version, client, features }`.
- `features` is a reserved list for post-1.0 capability negotiation. It is empty
  today; an unknown feature is ignored, not an error, so a later version can add
  one without changing the handshake.
- A mismatch returns `Response::Error(Invalid)` and closes the connection. The
  message names both versions so the operator knows which side to update.
- HTTP uses the same `Request` types but carries its version in the API contract
  rather than a socket handshake.
- At `1.0.0` the policy is frozen: the minimum supported version, deprecation
  window and feature-negotiation rules are decided then. Until then, the
  version constant, handshake, `features` field and changelog are the scaffold.

### Messages

- One `Request` enum and one `Response` enum, `type`/`data` tagged.
- A failure is always `Response::Error(WireError)`.
- Every operation that returns a collection returns a `Page<T>`; there is no
  `truncated`/`warning` triple.
- IDs are opaque and server-generated. A client never invents a terminal id.
- Unknown optional fields are tolerated on the wire; breaking changes bump the
  protocol version. Config, manifest and grant files are stricter (see below).

### Errors

```text
ErrorKind = NotFound | Forbidden | Unauthorized | Conflict
          | Invalid | Unsupported | TooLarge | TooMany | Internal
```

- `http_status()` and `exit_code()` are derived from the kind exactly once.
- `TooMany` is HTTP `429` and carries `Retry-After`; it is distinct from
  `Conflict`.
- `WireError` carries `kind`, a stable machine `code`, and a human `message`.
- HTTP body: `{"error":{"kind":"forbidden","code":"policy_off","message":"..."}}`.
- A plugin's own non-2xx result is a successful **call**, not a transport
  failure. The panel's transport failure and the plugin's outcome stay distinct.

### Pagination

```text
PageRequest { limit: Option<u16>, cursor: Option<String> }
Page<T>      { items: Vec<T>, next: Option<String>, total: Option<u64> }
```

- `limit` defaults to a documented value and is capped by the daemon.
- `cursor` is opaque to the client. It is not a path, an offset or an index the
  client may construct.
- `next = None` is the only end-of-list signal. An empty page is valid.
- `total` is optional because computing it can be as expensive as the listing;
  a feature that cannot answer it cheaply omits it.
- File reads keep `offset`/`next`; that is a cursor for a byte stream, not a
  handle. It is not shared with list pagination.
- Terminal handles are the only long-lived protocol ids.

### Interval

`anth-wire::parse_interval` is shared by `--watch` and `?interval=`. It requires
a `ms`/`s`/`m`/`h` suffix, rejects values below 10ms, and is tested against both
transports. The client owns the CLI loop; the browser gets SSE where it has no
loop.

## 6. Request lifecycle

```
CLI args ──┐
HTTP route ─┼─> Request ─> Daemon::execute ─> Response ─> transport-specific rendering
Socket frame┘
```

### The one dispatch

- `Daemon::execute(&self, Request) -> Response` is the only business-logic
  entry. Its match is exhaustive over `Request`.
- Per-feature modules implement functions such as
  `process::list(&Policy, &Ctx) -> Result<Response, WireError>`. They do not
  parse HTTP or clap.
- `dispatch.rs` owns the blocking classification: a request that reads `/etc`,
  walks `/proc`, touches a disk, shells out or runs wasm goes to
  `spawn_blocking`. `Echo` and pure in-memory answers do not.
- The socket and HTTP transports must not call feature functions directly. If a
  route needs a different answer, it needs a different `Request`.

### Adding an operation

The checklist is part of the contract, and a review must be able to tick it:

1. Add the data type and `Request`/`Response` variant in `anth-wire`; add a
   `Page` if it lists.
2. Add one arm in `dispatch.rs` that calls the feature module.
3. Add the feature implementation with its policy and guards.
4. Add the HTTP route that builds the `Request`.
5. Add the CLI branch that builds the same `Request`.
6. Add the docs entry (`api-endpoints.md`, `cli.md`, `socket-protocol.md`).
7. Add a contract test that drives the real entry point and, where applicable,
   a guard test that asserts the exact argv.

Do **not** add a second business-logic match. **Decided:** keep the one-match
dispatch plus a hand-written HTTP route table and CLI branch; do not generate
them from a command registry. Revisit only if a real route/request drift is
observed. A framework is not a substitute for a contract test.

### CLI rendering

The CLI mirrors the web presentation, not the old dense table. Group related
values under short section headings; do not label a field when the value is
already self-describing. `host-info` is the reference shape:

```text
Anthracite Panel · host.example
Debian 13 · kernel 6.12.111 · x86_64 · up 3d 4h

CPU
  AMD EPYC 7B13
  8 logical cores · load 0.12 0.20 0.31

Memory
  3.4 GiB / 7.6 GiB used (45%) · 4.2 GiB available

Swap
  not configured
```

- Keep the shape stable for `--watch`; on a TTY overwrite the frame, when
  redirected separate frames with a blank line.
- A border is optional; grouping and whitespace carry the structure.
- Human-readable sizes and durations live in one shared formatter, not in each
  feature renderer.
- Tests pin exact bytes for the normal, redirected and error cases.

### Concurrency and blocking

- The socket listener spawns one task per connection. A connection serves its
  requests in order.
- A slow request on one connection never blocks another connection.
- A blocking operation runs on `spawn_blocking`; no lock is held across an
  `.await`.
- Terminal reads, file waits and plugin calls are bounded by the daemon.
- A stateful service (terminal registry, upload table, session store) is owned by
  `Daemon` and shared through `Arc`; it is not stored in a global.

## 7. Configuration and state

### Files

| File | Contents | Mode | Who writes |
| --- | --- | --- | --- |
| `config.toml` | operator policy and paths | `0644` (no secrets) | operator, `config set`, API |
| `secrets.toml` | password hash, JWT signing key | `0600` | bootstrap, password change |
| `<state_dir>/sessions.toml` | refresh-token digests, chains, expiry | `0600` | login/refresh/logout |
| `<config_dir>/plugins.d/<id>.toml` | frozen grant per plugin | `0600` | install/approve |
| `<state_dir>/plugins.state.toml` | enabled/disabled preference | `0600` | enable/disable |
| `<state_dir>/` | parent directory for mutable state | `0700` | daemon |

All writes use a temporary file in the same directory, `fsync`, then `rename`.
The temporary file is created `0600` from the start. No write path loosens a
mode; a too-readable secrets file is reported and refused until fixed.

### Config schema

```toml

socket_path = "/var/tmp/anth.sock"
state_dir = "/var/lib/anth"

[server]

[log]

[terminal]

[process]

[network]
control = false

[firewall]
control = false

[volumes]
control = false

[accounts]
control = false
manage_passwords = false
allow_system = false
allow_privileged_groups = false

[files]

[auth]

[plugins]

install_from_web = false
require_signature = true
public_key = ""
fuel = 50000000
```

- `#[serde(default, deny_unknown_fields)]` on every section.
- `version` is mandatory in a file. An unknown major is refused with a
  migration message; a missing `version` is treated as a legacy v0.2 file and
  must go through `migrate`.
- Resolution order: CLI flag, environment, file, documented default.
- A missing file bootstraps; a file that exists and will not parse is refused.
- Relative paths in `config.toml` resolve against the **config file's
  directory**, not the process CWD. CLI/environment overrides stay as given.
- Release defaults: `/etc/anth/config.toml`, `/var/tmp/anth.sock`,
  `/var/lib/anth` (`state_dir`), `/etc/anth/secrets.toml`,
  `/etc/anth/plugins.d`, `/var/lib/anth/plugins`.
- Debug defaults: `./config.toml`, `./anth.sock`, `./state`, `./secrets.toml`,
  `./plugins.d`, `./plugins/bundles`. They keep `cargo run` root-free and local
  while leaving `plugins/<id>` for reference sources.
- Client subcommands use a non-writing load and never bootstrap secrets.

### Policy

`Policy` is built once at startup from `Config` plus the secrets/state handles.
It is immutable and shared. Each feature receives a typed sub-policy
(`ProcessPolicy`, `NetworkPolicy`, `FilePolicy`, ...), never the whole `Config`
and never a loose `bool`.

- Release defaults: every mutation off; empty allowlists deny; auth on;
  terminal off; plugins off.
- Debug defaults: enable the controls needed to test the UI, with a fixed
  harmless spawn allowlist, and print what was enabled. Password changes stay
  off.
- A config change that affects policy requires `restart` (or a service
  supervisor restart). An auth password change alone can swap the auth service
  and revoke sessions without a restart.

### Migration

`anth-panel migrate --from <config> [--write]` is the selected approach. It is
dry-run by default; `--write` applies the migration. Migration is explicit, not
automatic on first start:

- read a v0.2 `config.toml`;
- write a v0.3 `config.toml` with `version = 1`;
- move `[auth]` credential fields to `secrets.toml`;
- move live sessions out of the config if they can be represented, otherwise
  force a re-login and say so;
- leave the old file untouched; never migrate in place by default.

## 8. Authentication and authorization

### HTTP

- One operator account. First run has an open bootstrap; after registration the
  bootstrap is closed permanently.
- Password hashing: Argon2id, PHC string, OWASP interactive parameters. The
  iteration/parameter choice is in `secrets.toml` via the PHC string, not a
  separate config knob that can disagree with it.
- Access token: HS256 JWT, 15 minutes, `sub`, `iss`, `iat`, `exp`, `sid`,
  `kind=access`.
- Refresh token: opaque random 256-bit value, stored only as SHA-256, 30 days,
  single-use, rotated in a chain. Reuse revokes the whole chain.
- At most 10 live sessions per account; the oldest is dropped.
- Cookies: `anth_access` on `/`, `anth_refresh` on `/api/auth`; both `HttpOnly`,
  `SameSite=Strict`, `Secure` when configured. Bearer headers are accepted for
  scripts.
- Every mutating HTTP route checks `Origin` against `Host`; `SameSite` does not
  separate ports on the same host.
- Login is rate-limited per source; failures do not distinguish unknown user
  from wrong password.
- Password change revokes every session and is itself authenticated by the
  current password.
- Public routes are an explicit allowlist: `/healthz`, `/api/auth/state`,
  `/api/auth/register`, `/api/auth/login`, `/api/auth/refresh`, static assets.
  Everything else under `/api/` requires `Authed`.
- No account enumeration in state/login responses beyond "registered" (which
  the login form must know).

### Bootstrap

`[auth] bootstrap` selects the first-run mode:

| Value | Effect |
| --- | --- |
| `auto` | debug build uses `web`; release build uses `generated` |
| `generated` | generate a random password, write only its hash, print the password once to stderr |
| `web` | expose the registration form/route while no password exists; close permanently after the first registration |

Bootstrap runs only when `auth.enabled = true` and the account has no password
hash. An existing password is never overwritten. `web` in a release build is
allowed only when explicitly configured and logs a warning. `generated` never
writes the password to a log. `auth.enabled = false` skips bootstrap and leaves
any existing credential untouched.

`GET /api/auth/state` reports `required`, `registered`, `bootstrap`
(`"web"` or `"closed"`) and `username`; the shell shows the registration form
only for `bootstrap = "web"` and `registered = false`.

Detailed field/route proposal: [phase-0-contracts.md](phase-0-contracts.md).

### Socket

- **Decided:** no anonymous socket in release. The listener checks `SO_PEERCRED`
  and accepts only:
  - the daemon's own uid (the normal CLI case), or
  - uid 0 (root), or
  - a configured group/uid if the operator adds one.
- The socket is created `0660`; the parent directory is not world-writable.
- The socket protocol carries no user identity. The peer check is the identity.
- The check is documented in `socket-protocol.md`; an alternative client must
  run as an accepted peer.
- If a deployment cannot use peer credentials, it must expose HTTP with auth
  instead, not an open socket.

## 9. Plugins

### Bundle format

```
plugin.toml        manifest (declares files, capabilities, API/UI anchors)
plugin.wasm        guest module
plugin.sig         detached Ed25519 signature over plugin.toml
web/<module>.js    optional UI modules, each with a declared sha256
```

- `plugin.sig` signs the raw bytes of `plugin.toml`.
- `plugin.toml` declares `sha256` for `plugin.wasm` and for every `web/` module.
  Signing the manifest therefore approves every byte the host will load or
  serve.
- `manifest_version = 1` and `abi = 3` are explicit. An unknown manifest version
  is refused, not guessed.
- The module path is pinned to `plugin.wasm`.
- `require_signature` defaults to true. `false` is an explicit bypass that
  prints a warning and still verifies a signature that is present.
- **Decided:** install is local by default. Browser install is gated by
  `[plugins] install_from_web`, requires a signature, and shows a code-execution
  confirmation. It is off in release.
- Install order: open zip, reject entries/size/symlinks/duplicates, extract to
  staging with `O_NOFOLLOW`, verify signature, verify every hash, parse and
  validate the manifest, probe-compile the module, freeze the grant, then rename
  into place. Any refusal removes staging.
- At every load: verify the manifest signature against `[plugins] public_key`,
  re-hash every file, compare against the grant, and compile. A mismatch is a
  disabled entry with a reason; it is never a silent skip.

### Grant

- One file per plugin under `plugins.d/<id>.toml`, `0600`.
- The grant freezes the normalized capability list: program, argv template,
  typed arguments, host job name, plus the manifest hash/signature, bundle
  version and module hashes.
- The guest never sends an argv or a program. It names a capability and supplies
  values; the host validates each value with its own `ArgType` and renders the
  argv.
- A manifest that adds or changes a capability is refused until
  `plugin approve --accept-capabilities` rewrites the grant.
- The advertised capability list comes from the grant, never the manifest.

### Runtime

- `wasmi`, no JIT, no WASI, one engine per module and a fresh store/instance per
  call.
- Exactly two imports: `anth_exec` and `anth_log`.
- ABI 3 has three pipes (`anth_http`, `anth_cli`, `anth_direct`); one type per
  pipe, no shared envelope and no `kind` tag.
- Bounds: 50M fuel (configurable), 64 MiB guest memory, 30 s wall clock, 32
  capability calls per invocation, 64 KiB log, 4 MiB reply, 64 KiB host stdout.
- Outer timeout is a trap, not a polite refusal, so a guest cannot retry a
  deadline in a loop.
- Host jobs own the program, paths and secret handling. A private key never
  travels in argv, logs or a job reply.
- A plugin failure is a plugin outcome (`PluginReply { status, value }`); a
  missing/disabled/trapped plugin is a transport error.

### UI isolation

**Decided:** a plugin's web module runs in a sandboxed iframe, not on the panel
origin.

- The iframe loads a tiny host-owned bootstrap from the panel origin with
  `sandbox="allow-scripts"` (no `allow-same-origin` by default).
- The module receives an opaque origin, no panel cookies and no panel DOM.
- Communication is `postMessage` over a narrow bridge:
  - `getSnapshot()` for the declared anchor data;
  - `call(anchor, body)` proxied by the host with the operator session;
  - theme tokens and a locale string table, read-only.
- The host validates `event.source` and the frame's expected origin, then the
  plugin id, anchor path and method against the frozen grant, before proxying.
  The iframe cannot reach an arbitrary URL.
- UI assets are served only from the declared `web/` allowlist, with exact MIME
  types, `X-Content-Type-Options: nosniff`, `Cache-Control: no-store`, and a
  restrictive CSP.
- If the iframe bridge is deferred, the fallback is same-origin script plus
  signature, and the risk must be written in the threat model. It must not be a
  silent default.

## 10. Feature architecture

Every feature follows the same shape:

1. A read path that produces a snapshot from a host source and degrades
   unreadable fields to `unknown`/zero.
2. A mutation path that validates against a **fresh, unfitted** snapshot, builds
   an argv/plan, and runs it on a blocking worker.
3. One policy sub-struct; a disabled switch refuses before reading anything
   sensitive where possible.
4. A typed error mapped through `ErrorKind`.
5. CLI table rendering, HTTP route, frontend client and component.
6. Tests: pure parser, guard matrix, exact argv, real router/socket, and a
   real-tool test where a fake would hide a wrong invocation.

| Feature | Read source | Mutation switch | Guard highlights |
| --- | --- | --- | --- |
| Host info | `/proc`, `/etc/os-release` | none | pure; unreadable fields degrade |
| Processes | `/proc`, `/etc/passwd` | `process.control`, `process.spawn` | no pid 1/self/other users; signal allowlist; spawn allowlist; detached child reaped |
| Network | sysfs, `/proc/net/dev`, `getifaddrs` | `network.control`, `network.manage` | loopback/peer/default-route delete guards; rename only when down; fresh state |
| Firewall | `nft` managed table | `firewall.control` | only the managed `inet anthracite` table and its `input`/`output` chains; argv, never a shell; custom rules are not edited |
| Volumes/partitions | `lsblk`, mountinfo, swaps | `volumes.control/partition/format`, `disk_allow` | whole-disk and allowlist checks; no mounted/swap/busy disk; mount root; protected paths |
| Accounts | `/etc/passwd`, `/etc/group`, `/etc/shadow`, `getent` | `accounts.control`, `accounts.manage_passwords` | uid/gid 0, daemon account, last admin, `nss` read-only, system/privileged opt-in; `chpasswd` on stdin |
| Files | `files.root` | `files.write`, `files.trash`, archives | canonical path and symlink containment; no `..`; chunked reads/writes; size caps; safe archive members |
| Terminal | PTY | `terminal.enabled` | shell allowlist, max sessions, idle expiry, per-session lock, bounded read, `seq`, owner |
| Plugins | bundle + grant | `plugins.enabled`, `plugins.install_from_web` | signature, per-file hashes, frozen grant, bounds, UI sandbox |
| Lifecycle | system | `--allow-reboot` | restart vs reboot; 300 s cap; answer before action |

### Common invariants

- A guard reads the unfitted snapshot. A list that is too large is an explicit
  page, not a shorter snapshot.
- A mutation that needs a program runs an argv vector; no `sh -c`.
- `sudo` is a global, explicit policy; its absence falls back to a direct call
  where possible and reports the refusal otherwise.
- A process spawn is detached with null stdio and reaped by a thread per child;
  do not change the global `SIGCHLD` disposition, which the PTYs depend on.
- A file read refuses a non-regular file before opening it; opening a FIFO can
  block forever.
- A snapshot that is too large to send is a bug in the page contract, not a
  reason to shorten rows.

## 11. HTTP and streaming

### Routes

- `/healthz` — constant, public.
- `/api/auth/...` — state, register, login, refresh, logout, password.
- `/api/<feature>/...` — one route per command; bodies carry arguments at the
  top level, no wire envelope.
- SSE only where a browser watches a value: host info, processes, network.
  Event name, id, retry and keep-alive are part of the contract.
- `GET /api/terminal` — WebSocket; one connection owns one PTY; resize, input,
  close and exit are explicit frames.
- `/api/plugins/{id}/...` — anchors, resolved per id/alias.
- `/p/{id}/{module}` — declared plugin UI modules only.
- `/` and static assets — the SPA; unknown `/api` is JSON `404`; a missing
  file is `404`, not `index.html`.
- Plugin UI is served with the iframe bootstrap when the sandbox is enabled.

### Error shape

```json
{"error":{"kind":"forbidden","code":"policy_off","message":"process control is disabled"}}
```

- Status is derived from `kind`; the JSON `kind` and `code` are stable.
- A body axum rejects before the handler still answers in this shape.

### Streaming rules

- A bad interval is a `400` before the stream opens.
- After the first byte, a failure is an SSE `error` event and the stream ends.
- `EventSource` reconnects only while `readyState` is `CONNECTING`; a `CLOSED`
  source is a refusal and gets a Retry action, not a "reconnecting" badge.
- A slow tick does not cause a catch-up burst; use `MissedTickBehavior::Delay`.
- The CLI watch keeps one connection and one interval; the client owns the loop.

## 13. Observability

- Hand-rolled logger, no global subscriber: `human|json|off`, levels
  `error|warn|info|debug|trace`, stdout/stderr, passed as `Arc<Logger>`.
- Request events: operation name, status, duration, plugin id/pipe (never the
  payload). A refusal is `warn`, a successful call is `info`, a debug line is
  opt-in.
- Guest logs are data: escape newlines and control characters; cap total bytes;
  filter by the daemon level; never let a guest raise its own priority.
- Never log a password, token, private key, command line containing a secret, or
  a full file body. A host job that handles a secret returns only a redacted
  result.
- REPL: a queue sink drained around the prompt; non-TTY logs go to the chosen
  stream.
- `/healthz` is constant and credential-free. A readiness check that needs the
  config or plugin root can be separate and may fail.

## 15. Security model

| Threat | Boundary | Mitigation |
| --- | --- | --- |
| Unauthenticated HTTP caller | browser/API | auth on by default, `Authed`, session revocation, rate limit |
| CSRF from another site/port | browser | `SameSite=Strict` + Origin check on mutations |
| Leaked access token | browser/API | 15 min TTL, session check on every request |
| Leaked refresh token | state file | hashed at rest, single-use rotation, chain revocation |
| Local socket caller | Unix socket | `SO_PEERCRED`, `0660`, same uid/root/group only |
| Path traversal | files | canonical containment, reject `..`/symlinks, re-check at write |
| Shell injection | all mutations | argv vectors, no `sh -c`, typed validators |
| Privilege escalation | accounts/network/firewall/volumes | policy switches + guards, no root escape hatch |
| Malicious plugin guest | wasmi | frozen grant, no argv, fuel/memory/time/exec/log bounds |
| Tampered plugin bundle | install/load | Ed25519 manifest signature + per-file hashes + re-check on load |
| Malicious plugin web module | browser | sandboxed iframe, no panel origin/cookies, host proxy for anchors |
| Denial of service | any transport | frame/body/page limits, bounded waits, blocking pool, session caps |
| Secret leakage | logs/errors | redaction, no secret in argv, `0600` state, no body logging |
| Stale/forged config | startup | refuse parse errors, version field, migration tool |

### Protocol compatibility before 1.0.0

The project is pre-release, so the wire is allowed to break. The rule is
**break loudly and record it**, not "never break":

- Bump `PROTOCOL_VERSION` for any change that an older peer would misread.
- Update `anth-wire`, the CLI, the HTTP adapter, the frontend and the docs in the
  same change.
- Add an entry to `docs/design/protocol-changelog.md` with the old version, the
  new version and the client action (upgrade, re-login, migrate).
- Keep the mandatory `Hello`/`Welcome` handshake and the reserved `features`
  list. They are the scaffold, even while nothing negotiates yet.
- A mixed pair must fail with a message naming both versions. It must never
  parse a frame under the wrong schema.
- At `1.0.0`, decide the minimum supported version, the deprecation window, the
  feature-negotiation semantics and the migration policy. Until then, none of
  those are promises.

This applies to the wire protocol only. Config, manifest and grant files carry
their own `version`/`manifest_version` fields and always go through an explicit
migration or refusal.

## 19. Extra tasks

### Files: drag and drop in the explorer

**Goal:** move a file or directory in the Files explorer by dragging it onto a
folder, a breadcrumb or the empty area of the current directory.

This is one task with a backend prerequisite; it is not only a frontend
gesture:

- **Move operation first.** Add `files.move` over wire, HTTP, CLI and the
  client: source path plus destination directory (and optional new name).
  It requires `files.write`, resolves both paths under the file root, refuses
  `..`, symlink escapes and moving a directory into itself or a descendant,
  and does not overwrite by default. A missing source is `not_found`; an
  existing destination is `conflict` with `destination_exists`. Use a
  same-filesystem `rename`; a cross-device move is refused explicitly rather
  than silently copied.
- **Drop targets.** A row that is a directory, each breadcrumb segment, and the
  empty area of the current directory. Highlight the target only while a valid
  drag hovers it. Dropping onto the current directory is a no-op.
- **Source rules.** Files and directories are draggable. Dragging requires
  `files.write`; without it, rows are not draggable and no drop target is
  highlighted. The source row stays selected during the drag.
- **Conflicts.** Ask before replacing an existing destination. If the operator
  declines, nothing is sent. Do not offer a merge for directories in this
  task.
- **Feedback.** On success, refresh the listing, keep the moved row selected in
  its new directory when it is visible, and show a short localized notice. On
  failure, keep the listing and show the daemon message.
- **Pointer and touch.** Implement HTML5 drag events for a mouse and fall back
  to Pointer Events for pen/touch; touch does not emit HTML5 drag events
  reliably. A long-press is not required: a dedicated "Move" action can be the
  touch path if pointer dragging proves awkward. Do not make mobile drag the
  only way to move.
- **Out of scope.** Dragging files out of the browser to the operating system,
  dragging from the OS into the panel (existing upload covers that), and
  cross-device copy fallback.

**Tests:** pure path/guard tests for `files.move`; exact argv is not applicable
because the operation is in-process; HTTP/socket/CLI round trips; moving a file,
a directory, a symlink, into itself, onto an existing name and across the root
boundary; component tests for target detection, refusal without `files.write`,
conflict prompt and refresh; browser check with a mouse drag and a touch
pointer drag.

### Pending validation: real network, firewall and storage commands

The network mutation slice is implemented and covered by a scripted `ip`
runner, but the current development container cannot execute the real commands:
it has `iproute2` and `nftables`, yet its bounding set excludes
`CAP_NET_ADMIN`, and `unshare` is blocked, so a nested user/network namespace is
not an option either.

`scripts/dev.sh` builds the binary as the invoking user and then runs it through
`sudo`, so `cargo build` and Vite keep the caller's account. That covers a host
where root holds `CAP_NET_ADMIN`, but not a container whose bounding set excludes
it. To close this validation, start the development container with
`--cap-add=NET_ADMIN` and `--device /dev/net/tun`, then check:

```bash

nft --version
grep CapEff /proc/self/status      # bit 12 (0x1000) present
./scripts/dev.sh restart           # no capability warning
```

Run a real create/up/delete cycle on a throwaway dummy interface and a real
allow/deny/edit/flush/policy cycle on the managed firewall table.

The storage mount/unmount and partition/format slices have the same limitation:
they are covered by scripted `mount`/`umount` and `sfdisk`/`mkfs` runners, but
this container lacks `CAP_SYS_ADMIN`, so real mutations are refused. Add a
throwaway loop device to the validation once the container has the capability:
create a partition, format it, mount it under `/mnt`, unmount and delete the
partition.

Until then, the network, firewall and storage success paths are exercised only
with fake runners; permission and unsupported-tool paths are exercised for real.

Accounts do not share that limitation. On 2026-10-28 the development daemon,
running as root with shadow-utils installed, created a throwaway group and user,
