# Terminal

The daemon can run an interactive program on a pseudo-terminal and stream it to
the web panel and the CLI. This page covers the policy, the wire contract and
the web UI.

## Warning

A terminal is remote code execution. Anyone who can open a session gets a shell
as the user the daemon runs as.

The HTTP route needs the panel session when `[auth] enabled` is on, and the
upgrade also checks `Origin` against `Host`. The Unix socket has no
authentication beyond `SO_PEERCRED`; do not expose it to a network you do not
control.

## Enabling it

```toml
[terminal]
enabled = false
shell = "auto"
max_sessions = 4
idle_seconds = 900
```

| Key | Default | Meaning |
| --- | --- | --- |
| `enabled` | `false` | Serve terminal requests at all. |
| `shell` | `"auto"` | `auto` uses `$SHELL`, then the account login shell from `/etc/passwd`, then `/bin/sh`. An explicit value must be an absolute executable. The request never chooses a program. |
| `max_sessions` | `4` | Concurrent terminals across the daemon. Reaching it is a refusal, not an eviction. |
| `idle_seconds` | `900` | A session unused for this long is reaped. `0` disables expiry. |

The child gets a minimal environment (`TERM=xterm-256color`, `PATH`, `HOME`,
`LANG` and `LC_ALL=C.UTF-8`) and starts in `$HOME` when it exists. The daemon's
own environment is not inherited.

## Session model

- One PTY per WebSocket/CLI client; several tabs are several sessions.
- Handles are opaque and generated by the daemon (`t1a`, `t1b`, ...).
- The owner is the authenticated browser session id for HTTP and `socket:<uid>`
  for the local socket. A handle from another owner answers `not_found`.
- A read waits at most 30 seconds (`wait_ms` is capped); an empty answer means
  the wait expired, not that the program exited.
- `seq` starts at zero and advances only when bytes are returned, so a gap means
  a lost answer.
- A WebSocket disconnect closes its PTY and kills the process group. Closing the
  last web tab closes the window and its sessions. Reattaching after a network
  drop is not part of this slice.
- The terminal is off unless `[terminal] enabled = true`.

## Wire contract

Requests over the socket and the HTTP bridge:

```jsonc
{ "type": "terminal_open", "data": { "cols": 80, "rows": 24 } }
{ "type": "terminal_read", "data": { "id": "t1a", "wait_ms": 10000 } }
{ "type": "terminal_write", "data": { "id": "t1a", "bytes_base64": "bHMK" } }
{ "type": "terminal_resize", "data": { "id": "t1a", "cols": 120, "rows": 40 } }
{ "type": "terminal_close", "data": { "id": "t1a" } }
```

Answers:

```jsonc
{ "type": "terminal_opened", "data": { "id": "t1a", "program": "/bin/sh", "cols": 80, "rows": 24, "line_editing": false } }
{ "type": "terminal_output", "data": { "id": "t1a", "seq": 1, "bytes_base64": "aGkK", "eof": false } }
{ "type": "accepted" }
```

`terminal_output` with `eof: true` carries `exit_code` when the platform reports
it. Sizes are 1..500 columns/rows. Output chunks are at most 16 KiB; input is
capped at 16 KiB after decoding. Errors use the normal `WireError` shape;
`terminal_disabled` (`forbidden`), `terminal_capacity` (`conflict`), bad sizes
(`invalid`) and unknown handles (`not_found`) are the names clients branch on.

## HTTP and CLI

`GET /api/terminal?cols=80&rows=24` upgrades to a WebSocket. The browser and
server exchange JSON text frames:

```jsonc
// browser -> server
{ "type": "input", "data": "<base64>" }
{ "type": "resize", "cols": 120, "rows": 40 }
{ "type": "ping" }

// server -> browser
{ "type": "ready", "shell": "/bin/sh", "cols": 80, "rows": 24, "line_editing": false }
{ "type": "output", "data": "<base64>" }
{ "type": "exit", "code": 0 }
{ "type": "error", "detail": "…" }
{ "type": "pong" }
```

`ready` precedes any output. The bridge runs a long-poll read next to the input
loop, so typing does not wait for a quiet shell. The WebSocket frame cap is
128 KiB.

`anth-panel terminal [--cols N --rows N]` does the same over the socket. It puts
the local TTY in raw mode, forwards `SIGWINCH`, restores the TTY on exit and
returns the remote exit code.

## Web UI

The **Terminal** section opens a single global window with one tab per session.
Sessions survive navigating to Files or Settings because the window lives on
`document.body`; they end when the last tab/window closes.

- Tab strip with status dot, shell label, close and `+`.
- Full-bleed xterm.js surface, lazy loaded, fitted to the window.
- Mobile extended keyboard above the soft keyboard: `Ctrl`, `Alt`, `Esc`, `Tab`,
  arrows, `Home/End`, `PgUp/PgDn`, `^C`, `^D`, `^L`, `^Z` and common symbols.
  `Ctrl`/`Alt` are sticky for the next character key.
- Double-tap sends Tab; pinch changes font size; long-press and drag sends
  arrow keys; long-press selects text with the normal mobile selection UI.
- `A−`/`A+` change font size; the keyboard button hides the soft keyboard.
- A physical keyboard hides the soft keyboard and sends keys directly.
- xterm uses the panel theme; the shell with line editing (`bash`, `zsh`, ...)
  owns Up/Down and Tab. A minimal `dash` falls back to local history/Tab.

Reattach after a network drop, full-screen split panes, snippets and SFTP from
the terminal are deliberately outside this slice.

## Testing it by hand

With a daemon running and terminal enabled:

```bash
anth-panel terminal
```

From the web UI, open **Terminal**, press **Open terminal**, and run a command.
Resizing the window or rotating the device sends a resize; `stty size` should
follow. Closing the tab must remove the shell from the host.
